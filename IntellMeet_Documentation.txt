1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
What IntellMeet is:
IntellMeet is a comprehensive, full-stack video conferencing, real-time collaboration, and meeting productivity platform designed for professional and secure communication. Built using the MERN stack (MongoDB, Express.js, React.js, Node.js) alongside WebRTC and Socket.io, it offers an end-to-end solution for modern remote meetings.

Purpose of the project:
The primary purpose of IntellMeet is to provide a seamless, highly accessible, and intelligent meeting environment that doesn't just connect people visually and audibly, but also enhances post-meeting productivity. Through AI-driven meeting intelligence, it extracts summaries, key decisions, action items, and sentiments from meeting transcripts, transforming verbal discussions into structured assets.

Problems it solves:
- Dependency on expensive, enterprise-locked video conferencing tools.
- Difficulty in manually tracking meeting minutes, key decisions, and assigning action items.
- Lack of customizable, secure, and privacy-focused communication channels.
- Inefficient post-meeting workflow tracking.

Main objective of the platform:
To deliver a robust, scalable, and responsive real-time communication platform where users can instantly create or join secure meeting rooms, share their audio/video streams, communicate via text, schedule upcoming meetings, manage AI-generated summaries in a document hub, and update personalized meeting hardware preferences.

Real-world use cases of the project:
- Telehealth/Medical consultations where doctors and patients can securely connect, share streams, and automatically save clinical summaries and follow-ups.
- Remote enterprise team stand-ups, sprint planning, and retrospective sessions.
- Online education, virtual classrooms, and tutoring sessions.

Why this project is useful:
It packages essential remote collaboration features into a single, intuitive interface while introducing cutting-edge AI summarization, effectively reducing the administrative overhead of post-meeting reviews.

2. FEATURES OF THE PROJECT
--------------------------------------------------------------------------------
- User Authentication: Secure registration and login processes utilizing bcrypt for password hashing and JSON Web Tokens (JWT) for stateless session management.
- Register/Login system: Fully validated forms with clear error handling to guide users during account creation and dashboard access.
- JWT authentication: Stateless and secure authentication mechanism.
- Protected routes: Frontend and backend route guards ensuring only authenticated users can access the dashboard and meeting rooms.
- Dashboard: A centralized user hub to manage recent consultations, schedule meetings, access global chat, manage saved documents, and toggle account preferences.
- Meeting creation: Instant generation of unique, secure room IDs using UUIDs.
- Join meeting functionality: Ability to enter a specific room ID or shareable link and instantly connect to an ongoing session.
- Video calling: High-quality, low-latency peer-to-peer video streaming.
- WebRTC integration: Core technology used for establishing direct media streams between peers without going through a central server.
- Socket.io real-time communication: Signaling server implementation for WebRTC, handling room joining, chat messaging, and connection states.
- Screen sharing: Share entire screen/window/tab with dynamic stream replacement using replaceTrack() and automatic camera stream restoration.
- Camera and microphone access: Browser-native media device permission handling with hardware event state synchronizations.
- Global Chat Room: Persistent global chat room where authenticated users can converse in real-time, complete with custom styling, user indicators, and message history database persistence.
- Schedule Meetings: Dedicated scheduler allowing users to create future meetings with a title, date, and time, generating unique room links that can be copied directly to the clipboard.
- Saved Documents Management: A workspace panel displaying all saved meeting summaries. Users can search documents, delete records, or download them locally as TXT files.
- Meeting Preferences (Settings): Dedicated profile settings page allowing users to update their credentials and customize default join states (mute mic on join, turn off camera on join).
- Responsive UI: Fluid layouts and adaptive grids built with modern CSS to ensure perfect display on desktops, tablets, and mobile devices.

3. COMPLETE TECH STACK
--------------------------------------------------------------------------------
Frontend:
- React.js: Chosen for its component-based architecture, making it highly efficient to build interactive UIs like the meeting room and dashboard.
- React Router: Essential for single-page application (SPA) navigation, allowing seamless transitions between login, dashboard, and meeting rooms.
- Axios: A promise-based HTTP client used for making clean, reliable API requests to the backend.
- Vanilla CSS: Used for crafting a custom, responsive, and premium design system with dynamic layouts.
- Socket.io-client: Client-side WebSocket implementation to connect to the signaling and global chat server.

Backend:
- Node.js: Provides an asynchronous, event-driven JavaScript runtime environment perfect for handling concurrent connections in a real-time app.
- Express.js: A minimalist web framework that simplifies routing, middleware integration, and API endpoint creation.
- MongoDB: A NoSQL database that offers flexible schema design, perfect for storing varied user profiles, meetings, chats, documents, and scheduled sessions.
- Mongoose: An ODM (Object Data Modeling) library for MongoDB that provides schema validation and relationship mapping.

Realtime & Video:
- Socket.io: Enables bi-directional, event-based communication. It acts as the signaling server to exchange WebRTC connection details (offers, answers, ICE candidates) and drives the real-time global chat.
- WebRTC: Web Real-Time Communication API used for capturing and streaming audio and video directly between browsers.

AI Integration:
- Groq Cloud API / OpenAI SDK: Leverages the `llama-3.3-70b-versatile` model for lightning-fast, structured JSON meeting summaries, extracting key decisions, action items, and sentiment.

Authentication & Helpers:
- JWT (JSON Web Tokens): Used for securely transmitting information between parties as a JSON object, specifically for stateless user sessions.
- bcryptjs: A password-hashing function designed to securely store user credentials in the database.
- UUID: Used to generate unique room identifiers for instant and scheduled meetings.

Deployment:
- Vercel: Ideal for hosting the React frontend with instant CI/CD.
- Render / Railway: Suitable for hosting the Node.js/Socket.io backend, ensuring WebSocket connections remain stable.

4. PROJECT ARCHITECTURE
--------------------------------------------------------------------------------
- Frontend flow: The React app initializes. If a user has a valid JWT in local storage, they access the Dashboard. They interact with UI components which trigger Axios requests or Socket.io events.
- Backend flow: Express server listens for HTTP requests and Socket.io events. Middleware intercepts secure API calls to verify JWTs before passing requests to controllers.
- API communication: RESTful architecture where the client requests data (e.g., GET /api/meetings) and the server responds with JSON.
- Database interaction: Controllers use Mongoose models to query or mutate documents in MongoDB (e.g., saving a new user, meeting record, message, scheduled meeting, or document).
- Socket connection flow: When a user enters a room, the frontend Socket.io client emits a "join-room" event. The server places the socket in a specific room and broadcasts the presence to other users.
- WebRTC peer connection flow: 
  1. User A joins and signals presence.
  2. User B joins, receives User A's presence, and creates an RTCPeerConnection.
  3. User B creates an 'Offer' and sends it via Socket.io to User A.
  4. User A receives the 'Offer', sets remote description, creates an 'Answer', and sends it back.
  5. Both exchange ICE candidates (network routing info) to establish a direct P2P media stream.
- Authentication flow: User submits credentials -> Server hashes/verifies password -> Server issues JWT -> Client stores JWT -> Client sends JWT in Authorization header for subsequent requests.
- AI Documents Generation flow: User submits a transcript -> Server calls Groq API -> Parses structured JSON data -> Saves to Meeting document -> Automatically creates a standalone Document record for the user's workspace.

5. HOW THE PROJECT WORKS STEP BY STEP
--------------------------------------------------------------------------------
1. User creates account: The user fills out the registration form. The client sends data to `/api/auth/register` (uses bcrypt for secure hashing).
2. User logs in: User enters credentials. Backend verifies them and returns a JWT token and user profile object. The client stores the token/user and redirects to the Dashboard.
3. User accesses Dashboard: The dashboard loads the default "Home" page, fetching the user's past meetings, saved documents count, and scheduled sessions.
4. User updates settings: In the "Settings" tab, the user can modify their display name, email, password, and default hardware toggles (e.g. mute mic on join). These updates are saved in MongoDB.
5. User schedules a meeting: In the "Schedule Meeting" tab, the user fills in a title, date, and time. The app generates a UUID-based meeting link. This record is saved to the scheduled meetings list and the link can be copied to the clipboard.
6. User starts/joins a meeting: The user clicks "Start Meeting" or joins an active room by ID. The hardware toggles set in user settings are automatically applied to the camera and microphone.
7. WebRTC exchange starts: Upon entering the meeting room, the browser requests camera/mic permissions. Once granted, the Socket.io connection coordinates the WebRTC signaling (Offer/Answer/ICE) between peers.
8. Real-time collaboration: Peer streams are connected. Users can chat inside the meeting, toggle camera/microphone states, and share their screens.
9. Generating AI summaries: Post-meeting, a user clicks "AI Summary" on the dashboard. They paste a transcript (or use the built-in example template) and hit generate.
10. AI Summary Processing: The Groq API analyzes the transcript and outputs a structured summary, action items (with assignees and deadlines), decisions, and sentiment.
11. Document persistence: The summary is saved to the Meeting record and automatically added to the "Documents" workspace.
12. Accessing saved documents: In the "Document" tab, the user can search through saved summaries, download a compiled TXT file of a meeting's intelligence, or delete obsolete summaries.
13. Global Chat: In the "Chat Room" tab, the user connects to a persistent room where all logged-in platform users can exchange messages, synced in real-time and backed by database history.

9. DATABASE DESIGN
--------------------------------------------------------------------------------
User Schema:
- Fields:
  * name (String)
  * email (String, unique)
  * password (String, hashed)
  * settings (Object: { muteMicOnJoin: Boolean, disableCameraOnJoin: Boolean })
- Purpose: Stores user credentials, email validation keys, and default meeting hardware preferences.

Meeting Schema:
- Fields:
  * title (String)
  * roomId (String, unique UUID)
  * createdBy (ObjectId, ref: User)
  * participants (Array of ObjectIds, ref: User)
  * transcript (String)
  * summary (String)
  * actionItems (Array of Objects: { task: String, assignee: String, deadline: String })
  * decisionPoints (Array of Strings)
  * sentiment (String)
- Purpose: Tracks completed or ongoing meeting records and hosts their summary metadata.

Document Schema:
- Fields:
  * title (String)
  * summary (String)
  * actionItems (Array of Objects: { task: String, assignee: String, deadline: String })
  * decisionPoints (Array of Strings)
  * sentiment (String)
  * createdBy (ObjectId, ref: User)
- Purpose: Stores isolated meeting intelligence summaries inside the user's workspace, supporting file download.

ChatMessage Schema:
- Fields:
  * sender (String)
  * message (String)
  * timestamps
- Purpose: Maintains a persistent record of global chat conversations.

ScheduledMeeting Schema:
- Fields:
  * title (String)
  * date (String)
  * time (String)
  * participants (Array of Strings)
  * meetingLink (String)
  * createdBy (ObjectId, ref: User)
- Purpose: Tracks future meetings created by users for scheduling purposes.

10. API ENDPOINTS
--------------------------------------------------------------------------------
Authentication:
- `POST /api/auth/register` - Create user profile and generate token.
- `POST /api/auth/login` - Verify user credentials and generate session token.

Meetings:
- `POST /api/meetings/` (Protected) - Instantiate new meeting and register room ID.
- `GET /api/meetings/` (Protected) - Fetch meeting list containing current user as participant.
- `POST /api/meetings/join/:roomId` (Protected) - Append user to a meeting's participant array.
- `POST /api/meetings/:roomId/generate-summary` (Protected) - Process transcript, trigger AI service, and create document.

Documents:
- `GET /api/documents` (Protected) - Retrieve saved documents for the active user.
- `POST /api/documents` (Protected) - Manually create a document.
- `DELETE /api/documents/:id` (Protected) - Delete document by database ID.

Chat Room:
- `GET /api/chat/messages` (Protected) - Fetch history of global chat room messages.

Scheduled Meetings:
- `GET /api/scheduled-meetings` (Protected) - Retrieve user's future meetings.
- `POST /api/scheduled-meetings` (Protected) - Register a future meeting.
- `DELETE /api/scheduled-meetings/:id` (Protected) - Cancel/delete scheduled meeting.

Settings:
- `GET /api/settings` (Protected) - Retrieve current user's profile and settings.
- `PUT /api/settings` (Protected) - Update name, email, password, and hardware preferences.

11. SECURITY IMPLEMENTATION
--------------------------------------------------------------------------------
- Password Security: Hashed with bcryptjs (salt rounds = 10) before MongoDB saves.
- Router Security: REST controllers protect endpoint calls with `authMiddleware`, verifying JWT validity. Frontend router blocks unauthenticated pages using a `<ProtectedRoute>` wrapper.
- Authorization Checks: API routes verify ownership before mutating resources (e.g., verifying a user is a participant before generating summaries, and checking the `createdBy` field before deleting scheduled meetings/documents).
- CORS Configuration: CORS rules restrict access to the Express app and Socket endpoints to configured domains.
- Environment Isolation: Crucial API keys, JWT secrets, and DB URLs are saved in a local `.env` file, excluded from source control.

--------------------------------------------------------------------------------
12. CHALLENGES & SOLUTIONS
--------------------------------------------------------------------------------
- Asynchronous WebRTC Signaling: Deferring ICE candidate storage when the local description is not fully set was resolved by establishing connection-state handlers.
- WebSocket State Synchronization: Handling socket disconnects and page refreshes. Mitigated by room isolation and clearing socket listener bindings on React components' unmount.
- Media Stream Permissions & Settings: Gracefully managing rejected camera/mic permissions. IntellMeet uses settings check hooks to auto-mute or disable video tracks according to user preference.
- AI Service Limits & Fallbacks: Integrated error catch checks in `aiService.js` to handle 429 rate limits or quota overages, falling back on mock templates while keeping the front-end active.
- File Assembly in Browser: Compiling structured summary text into a client-downloadable file was solved by assembling text structures inside a text-plain Blob object and downloading via simulated links.

15. COMPLETE PROJECT WORKFLOW SUMMARY
--------------------------------------------------------------------------------
1. Authentication: User signs in, receiving a JWT which the browser saves in localStorage.
2. Setup: User goes to Settings and sets preference toggles.
3. Scheduling: User schedules a future sync, copies the invite link, and distributes it.
4. Meeting Launch: User clicks to join the room. Settings are checked, camera/mic tracks are toggled to match user settings, and Socket.io connects the client to signaling.
5. Live Stream: WebRTC establishes a peer-to-peer connection. Video, audio, screen tracks, and chat messages exchange in real-time.
6. Summary Trigger: After meeting closure, the user copies the meeting chat/transcript, opens the AI modal, and triggers the summary generation request.
7. AI parsing: The Groq API analyzes the text, extracts action items, decisions, and sentiment, saves the results to the meeting document, and writes a copy to the Documents dashboard tab.
8. Document Access: User opens the Documents tab, searches for the meeting, and downloads a clean summary TXT file.
